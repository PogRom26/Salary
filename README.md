# Salary

Система расчёта заработной платы сотрудников B2B-направления по выгрузкам из 1С.

Расчёт выполняется в два этапа:

1. исходные Excel-файлы преобразуются в отдельный JSON для каждого сотрудника;
2. итоговые PDF формируются только из сохранённых JSON.

Такое разделение позволяет проверить расчёт, заполнить комментарии к ПДЗ,
дополнительные выплаты и другие ручные поля до создания итогового PDF.

## Быстрый запуск

Из корня проекта:

```bash
python calculate_salary.py
python main.py
```

Если используется виртуальное окружение проекта:

```bash
./venv1/bin/python calculate_salary.py
./venv1/bin/python main.py
```

`calculate_salary.py` читает Excel и создаёт JSON. `main.py` не пересчитывает
зарплату и не читает Excel: он формирует PDF из существующих JSON.

## Рабочий процесс

1. Создать папку `Data/<год>/<месяц>`.
2. Поместить в неё все обязательные выгрузки.
3. Запустить `calculate_salary.py`.
4. При необходимости отредактировать ручные поля в JSON:
   - комментарии к ПДЗ;
   - дополнительные выплаты;
   - прибыль и бонус по ключевым клиентам.
5. Проверить синтаксис JSON и запустить `main.py`.

Повторный запуск `calculate_salary.py` перезаписывает расчётные JSON. Поэтому
ручные комментарии следует добавлять после расчёта и до запуска `main.py`.

JSON должен оставаться валидным: строки заключаются в двойные кавычки, а
перенос строки внутри значения записывается как `\n`. Обычный перенос внутри
незакрытой строки приведёт к `JSONDecodeError`.

## Выбор расчётного периода

Программа автоматически выбирает максимальный числовой год и максимальный
числовой месяц внутри папки `Data`.

Пример:

```text
Data/
└── 2026/
    ├── 4/
    └── 6/   ← будет выбран этот период
```

Для расчёта старого периода временно уберите более новые папки либо доработайте
передачу периода в точку запуска.

## Исходные файлы

Все файлы помещаются в `Data/<год>/<месяц>`. Поддерживаются `.xlsx` и `.xls`.
Имена могут отличаться, но должны содержать следующие маркеры.

| Тип | Маркер в имени | Пример |
|---|---|---|
| Доход и прибыль | `profit` | `profit.xlsx` |
| Продажи брендов | `brand` | `brand_sales.xlsx` |
| Дебиторская задолженность | `debt` | `debt.xlsx` |
| Коммуникации | `коммуникации` | `Коммуникации за прошедший месяц.xlsx` |
| Цикл сделки | `цикл` | `Отчет по циклу сделки. Итого.xlsx` |
| Табель | `табель` | `Табель.xlsx` |

В периоде может быть несколько файлов, содержащих `табель`. Они будут прочитаны
и объединены. Для остальных типов используется один найденный файл.

### `profit`

Обязательные заголовки в отчёте:

- менеджер;
- сумма продажи;
- доход текущий;
- рентабельность текущая.

Для менеджеров используются строки с полным ФИО. Для руководителя используются
общие значения из строки `Итого`.

### `brand_sales`

Ожидается стандартная иерархическая выгрузка 1С:

- колонка A — сотрудник или дата документа;
- колонка D — название KPI/бренда;
- колонка F — план;
- колонка H — факт;
- колонка I — процент выполнения.

В отчёте должны присутствовать строки `ZIC`, `B2B Прибыль`, специальные продукты
и, при наличии продаж, `Лукойл`.

### `debt`

Обязательные колонки:

- `Контрагент`;
- `Основной менеджер`;
- `Просрочено`.

Дополнительные колонки допустимы. Строки с ПДЗ от порога, заданного в настройках,
попадают в отдельную таблицу с полем комментария.

### Коммуникации

Ожидается иерархический отчёт, где первая колонка содержит группы вида
`>> ГРУППА:`. Поддерживаются типы:

- визит к клиенту;
- звонок;
- отправить данные;
- подписание документов.

Для каждого типа считывается общее количество, успешно и неудачно завершённые
события.

### Цикл сделки

Обязательные колонки:

- `Сделки` либо колонка с процессами/событиями;
- `Дата первичного контакта`;
- `Дата последнего изменения`.

Расчёт использует иерархические группы сотрудников и стадий сделки.

### Табель

Ожидаются:

- первая колонка — сокращённое имя сотрудника;
- вторая колонка — итоговое количество отработанных часов.

Если табелей несколько, строки всех файлов объединяются до поиска сотрудника.

## Результаты

Файлы сохраняются в:

```text
Report/<год>/<месяц>/
```

Имена формируются по шаблону:

```text
<Фамилия>_<год>_<месяц>.json
<Фамилия>_<год>_<месяц>.pdf
```

Для каждого сотрудника создаётся собственный JSON и PDF. DOCX в текущем
процессе не создаются.

## Точки запуска

### `calculate_salary.py`

Основная точка расчёта. Загружает последний период, рассчитывает менеджеров и
руководителя, затем сохраняет все JSON.

### `main.py`

Основная точка генерации документов. Читает JSON последнего периода и выбирает
PDF-генератор по полю `report_type`.

### `manager_salary.py`

Рассчитывает и перезаписывает JSON только менеджеров. Удобен, когда JSON
руководителя уже содержит ручные комментарии, которые нельзя терять.

### `chief_salary.py`

Содержит расчёт KPI и итоговой зарплаты руководителя B2B-направления.

### `config.py`

Все изменяемые параметры расчёта:

- ФИО руководителя;
- базовые размеры бонусов;
- ставки и коэффициенты;
- веса специальных продуктов;
- стоимость часа;
- процент ответственности и порог детализации ПДЗ.

## Описание модулей

### Парсеры

- `parsers/excel_reader.py` — открывает `.xlsx` через `openpyxl`, а `.xls` через
  `xlrd`.
- `parsers/profit_parser.py` — находит показатели продаж, дохода и
  рентабельности менеджеров и строку `Итого` для руководителя.
- `parsers/brand_parser.py` — считывает план, факт и выполнение KPI по брендам.
- `parsers/debt_parser.py` — рассчитывает ПДЗ и формирует список крупных долгов
  по менеджеру или всему направлению.
- `parsers/comm_parser.py` — собирает статистику коммуникаций по сотрудникам.
- `parsers/cycle_parser.py` — рассчитывает плановый и фактический цикл сделки.
- `parsers/timesheet_parser.py` — ищет сотрудника в табеле и рассчитывает оклад.
- `parsers/__init__.py` — обозначает каталог как Python-пакет.

### Сервисы

- `services/calculation_context.py` — находит входные файлы, читает их и создаёт
  экземпляры всех парсеров.
- `services/file_finder.py` — определяет тип файла по маркеру в имени.
- `services/period_finder.py` — выбирает последний доступный год и месяц.
- `services/report_builder.py` — собирает менеджерский расчёт в единый словарь,
  который затем сохраняется как JSON.
- `services/report_io.py` — формирует имена файлов, сохраняет и загружает JSON.
- `services/__init__.py` — обозначает каталог как Python-пакет.

### Генераторы

- `generators/pdf_generator.py` — формирует PDF менеджера.
- `generators/chief_pdf_generator.py` — формирует PDF руководителя.
- `generators/docx_generator.py` — сохранённый старый генератор DOCX. Текущими
  точками запуска не используется.
- `generators/__init__.py` — обозначает каталог как Python-пакет.

### Модели и ресурсы

- `models/employee_report.py` — dataclass-модели ранней версии расчёта. Текущий
  конвейер использует словари/JSON напрямую; файл сохранён для совместимости и
  возможного дальнейшего перехода на типизированные модели.
- `models/__init__.py` — обозначает каталог как Python-пакет.
- `fonts/DejaVuSans*.ttf` — шрифты с поддержкой кириллицы для PDF.
- `fonts/__init__.py` — обозначает каталог как Python-пакет.

## Зависимости

- Python 3.10+;
- `pandas` — чтение и обработка таблиц;
- `openpyxl` — чтение `.xlsx`;
- `xlrd` — чтение `.xls`;
- `reportlab` — создание PDF.

Установка:

```bash
python -m pip install -r requirements.txt
```

## Диагностика

### Не найден исходный файл

Проверьте папку последнего периода и маркер в имени файла. Программа выводит
список отсутствующих типов.

### `JSONDecodeError`

Проверьте JSON-файл, указанный в ошибке. Обычно причина — незакрытая кавычка,
неэкранированный перенос строки или лишняя запятая.

Проверка файла:

```bash
python -m json.tool "Report/2026/6/Сотрудник_2026_июнь.json"
```

### PDF не учитывает новые Excel-файлы

`main.py` читает только JSON. Сначала запустите `calculate_salary.py`, затем
повторно сформируйте PDF через `main.py`.
